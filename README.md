# mcp-opencart

[English](README.en.md) | **Русский**

MCP-сервер для [OpenCart](https://www.opencart.com/) в одном PHP-файле. Подключает Claude и другие MCP-клиенты к интернет-магазину: товары, категории, производители, атрибуты, статьи, заказы, клиенты, отзывы, отчёт по продажам.

Поддерживаются **OpenCart 3.0.x** (в том числе ocStore 3), **4.0.x** и **4.1.x**. Версию и различия в схеме базы файл определяет сам.

## Как это устроено

У OpenCart нет отдельных обработчиков админки, которые можно было бы вызвать извне, а поднимать фреймворк целиком ради одного запроса сложно и у 3.x и 4.x он разный. Поэтому `mcp-opencart.php` читает настройки базы из `config.php` и пишет в таблицы **те же строки, что пишут модели админки**:

- описания на каждом языке магазина (`*_description`);
- привязку к магазинам (`*_to_store`);
- дерево категорий (`category_path`), которое пересобирается при создании и переносе;
- SEO-URL в формате своей версии: `query = product_id=42` в 3.x, `key` / `value` в 4.x, полный путь категорий (`noutbuki/apple`) в 4.x;
- акции: `product_special` в 3.x и 4.0, `product_discount` со `special = 1` в 4.1;
- артикулы SKU, UPC, EAN и прочие: колонки `product` до 4.0, таблица `product_code` в 4.1.

Тексты хранятся экранированными, как их сохраняет админка. После каждой записи чистится кеш OpenCart. Файлы движка не изменяются.

Дополнительные колонки форков подхватываются автоматически. Например, `meta_h1` в ocStore появляется в инструментах товаров и категорий, если есть в базе.

## Требования

- OpenCart 3.0.x, 4.0.x или 4.1.x.
- PHP 7.4+ с `pdo_mysql`, `curl`, `mbstring`.
- MySQL или MariaDB.

## Как проверялось

- **Движки:** чистые установки OpenCart 3.0.4.1, 4.0.2.3, 4.1.0.4 и ocStore 3.0.3.7, у каждого по два языка.
- **Веб-серверы:** встроенный сервер PHP, Apache с mod_php, Apache с PHP-FPM, nginx с PHP-FPM.
- **Клиент:** официальный MCP SDK для Python (Streamable HTTP): `initialize`, `tools/list`, `ping`, `tools/call`, ошибки инструментов.
- **Витрина и админка:** созданные товары, категории, производители и статьи открываются на витрине и в формах админки без ошибок PHP. Работают SEO-ссылки, акции, атрибуты, `meta_h1` в ocStore.
- **Заказы:** оформлены через настоящую корзину гостем (наложенный платёж, фиксированная доставка) на всех четырёх магазинах, затем прочитаны, сменён статус, построен отчёт. Отзывы оставлены с витрины и опубликованы через MCP.
- **Нагрузка:** 20 000 товаров и 10 000 заказов. Поиск, фильтры, отчёт и запись укладываются в 200 мс.
- **PHP 7.4:** код проверен на синтаксис и функции новее 7.4. Запуск на 7.4 не проводился (основная проверка шла на PHP 8.3).

## Установка

1. Положите `mcp-opencart.php` в корень магазина, рядом с `config.php`.
2. Откройте файл и задайте ключ, не короче 16 символов:

   ```php
   const MCP_KEY = 'длинный-случайный-ключ';
   ```

   С пустым ключом сервер отвечает `503` и ничего не делает.
3. Подключите MCP-сервер в клиенте.

**Claude (claude.ai, приложение)**, пользовательский коннектор:

- URL: `https://example.com/mcp-opencart.php`
- заголовок: `Authorization: Bearer <ключ>`

**Claude Code:**

```bash
claude mcp add --transport http opencart https://example.com/mcp-opencart.php \
  --header "Authorization: Bearer <ключ>"
```

Проверка с сервера:

```bash
curl -s -X POST https://example.com/mcp-opencart.php \
  -H 'Authorization: Bearer <ключ>' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"ping"}'
# {"jsonrpc":"2.0","id":1,"result":{}}
```

## Авторизация

| Способ | Пример |
|---|---|
| Заголовок Bearer | `Authorization: Bearer <ключ>` |
| Свой заголовок | `X-MCP-Key: <ключ>` |
| Параметр URL | `?key=<ключ>` |

Лучше передавать ключ в заголовке: параметр URL попадает в логи веб-сервера.

**Apache с PHP-FPM** (и другие CGI-схемы) по умолчанию не передаёт в PHP заголовок `Authorization`, и сервер отвечает 401. Есть два выхода:

- передавать ключ в заголовке `X-MCP-Key`, он доходит всегда;
- или добавить в `.htaccess` в корне магазина:

  ```apache
  <Files "mcp-opencart.php">
      CGIPassAuth On
  </Files>
  ```

  На Apache старше 2.4.13 вместо этого: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`.

С Apache + mod_php и с nginx + PHP-FPM `Authorization: Bearer` работает без настройки.

Ключ даёт полный доступ к магазину, как у администратора. Сравнение идёт через `hash_equals()`.

## Настройки

В начале файла:

```php
const MCP_KEY       = '';              // ключ доступа, минимум 16 символов
const MCP_READONLY  = false;           // true — только инструменты чтения
const MCP_ALLOW_SQL = true;            // инструмент sql_select
const MCP_IMAGE_DIR = 'catalog/mcp/';  // куда скачиваются картинки, относительно image/
```

## Инструменты (32)

**Магазин**

| Инструмент | Что делает |
|---|---|
| `shop_info` | Версия, адрес, языки, валюты, магазины, счётчики и все id, нужные другим инструментам: статусы заказов, наличия, классы налогов, веса, размеров, группы клиентов |
| `cache_clear` | Очистка кеша OpenCart (`system/storage/cache`) |

**Товары**

| Инструмент | Что делает |
|---|---|
| `product_list` | Поиск по названию, модели, SKU или id; фильтры по категории (с подкатегориями), производителю, статусу, цене, остатку, наличию акции; сортировка |
| `product_get` | Карточка целиком: тексты на всех языках, артикулы, цена, акции, скидки, остаток, картинки, категории, атрибуты, опции, SEO |
| `product_add` | Создание. Обязательны `name` и `model` |
| `product_edit` | Правка: меняются только переданные поля |
| `product_delete` | Удаление со всеми связями. В заказах остаётся копия товара |

Что можно передать при создании и правке:

- `image`, `images` — ссылки на картинки скачиваются в `image/catalog/mcp/`, пути вида `catalog/demo/x.jpg` берутся как есть;
- `categories` — список id;
- `manufacturer` — имя производителя: найдётся или создастся;
- `attributes` — `{"Память": "256 ГБ", "Цвет": {"uk-ua": "Титан", "ru-ru": "Титан"}}`; новые атрибуты создаются по имени, в группе `attribute_group`;
- `special_price`, `special_start`, `special_end` — акционная цена для группы клиентов по умолчанию, `0` убирает её;
- `sku`, `upc`, `ean`, `jan`, `isbn`, `mpn`, `price`, `quantity`, `status`, вес, размеры, `stock_status_id`, `tax_class_id` и другие поля формы;
- `seo_keyword` или `seo_keywords` по языкам. Если не передать, ключ при создании делается транслитом из названия;
- `stores` — список магазинов. При смене списка текущие SEO-ключи переносятся на новые магазины.

**Категории, производители, атрибуты, статьи**

| Инструмент | Что делает |
|---|---|
| `category_list` | Дерево с путями «Родитель > Потомок» и числом товаров |
| `category_get` | Категория с текстами на всех языках и SEO |
| `category_add` / `category_edit` | Создание и правка; смена `parent_id` переносит всю ветку, `category_path` и SEO-пути пересобираются |
| `category_delete` | Удаление вместе с подкатегориями. Товары остаются |
| `manufacturer_list` / `manufacturer_add` / `manufacturer_edit` / `manufacturer_delete` | Производители. В ocStore также описание, `meta_title`, `meta_h1`. Удаление используемого производителя только с `force: true` |
| `attribute_list` | Атрибуты по группам |
| `information_list` / `information_get` / `information_add` / `information_edit` / `information_delete` | Статьи раздела «Информация»: доставка, оплата, о нас |

**Заказы, клиенты, отзывы, отчёты**

| Инструмент | Что делает |
|---|---|
| `order_list` | Заказы с фильтрами по статусу, клиенту, датам. Незавершённые оформления (статус 0) скрыты, если не передать `include_missing` |
| `order_get` | Заказ целиком: клиент, адреса, способы оплаты и доставки, товары с опциями, итоги, история статусов |
| `order_status_set` | Новый статус и запись в историю |
| `customer_list` | Клиенты с числом заказов и суммой покупок |
| `review_list` / `review_status` / `review_delete` | Модерация отзывов; рейтинг товара пересчитывается |
| `sales_report` | Заказы, товары и выручка по дням, неделям, месяцам или годам и топ-10 товаров. По умолчанию считаются статусы «в обработке» и «выполнен» из настроек магазина |
| `sql_select` | Один запрос только на чтение (`SELECT`, `SHOW`, `DESCRIBE`, `EXPLAIN`) в транзакции read-only. Таблицы пишутся как `{product}`, префикс подставляется сам. Не больше 500 строк |
| `image_upload` | Скачать картинку по ссылке и получить путь для полей `image` |

## Языки

Магазин может быть многоязычным, поэтому у текстовых полей два режима:

- **Создание.** Поля верхнего уровня (`name`, `description`, `meta_title`…) пишутся во все языки. Объект `descriptions` задаёт свой текст отдельному языку:

  ```json
  {
    "name": "iPhone 15 Pro",
    "model": "IP15P",
    "descriptions": { "uk-ua": { "name": "iPhone 15 Про", "description": "<p>Опис</p>" } }
  }
  ```

- **Правка.** Поля верхнего уровня меняют язык из `language` (по умолчанию язык магазина), `"language": "all"` меняет все языки сразу.

Если `meta_title` не задан, он берётся из названия, как в админке.

## Ограничения

- `order_status_set` меняет статус и пишет историю, но **не отправляет письмо** клиенту и не запускает события OpenCart: списание остатков, бонусные баллы, вебхуки модулей. Если клиент должен получить уведомление, меняйте статус в админке.
- Опции товаров, варианты 4.x, оптовые скидки, связанные товары и загрузки читаются, но не редактируются. Для них остаётся админка.
- Заказы не создаются: это делает только оформление на витрине.

## Надёжность записи

В OpenCart 3 таблицы созданы на MyISAM, а там транзакций нет. Поэтому все проверки идут до первой записи: категории, языки, магазины, картинки (они скачиваются заранее). Неверный запрос не оставит в базе половину товара. В OpenCart 4 (InnoDB) каждая запись дополнительно выполняется в транзакции.

## Безопасность

- Ключ сравнивается через `hash_equals()`, без сессий и cookie. Ключ короче 16 символов отключает сервер.
- Картинки скачиваются только по http(s), не больше 20 МБ. Адреса локальных и служебных сетей блокируются (защита от SSRF). Тип проверяется по содержимому: принимаются JPEG, PNG, GIF и WebP.
- Пути картинок не могут выйти за пределы папки `image/`.
- Все запросы к базе подготовленные (prepared statements).
- `sql_select` пропускает один оператор только на чтение, в транзакции read-only, без `INTO OUTFILE`, `LOAD_FILE`, `SLEEP` и блокировок. Его можно выключить (`MCP_ALLOW_SQL = false`).
- `MCP_READONLY = true` убирает из списка все инструменты записи.

Если перед сайтом стоит антибот или WAF с JS-проверкой, добавьте `/mcp-opencart.php` в исключения. Иначе клиент получит страницу проверки вместо JSON.

## Протокол

MCP Streamable HTTP: JSON-RPC 2.0 через `POST`, ответ `application/json`, без SSE и сессий. Поддерживаются `initialize`, `ping`, `tools/list`, `tools/call`. Версии протокола: `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`.

## Решение проблем

| Симптом | Причина |
|---|---|
| 503 «Server disabled» | Не задан `MCP_KEY` или он короче 16 символов |
| 401 | Неверный ключ, или заголовок `Authorization` не доходит до PHP (Apache + PHP-FPM): используйте `X-MCP-Key` или `CGIPassAuth On`, см. «Авторизация» |
| 405 | Адрес открыт в браузере (GET). Сервер принимает только POST |
| 500 «config.php not found» | Файл лежит не в корне магазина |
| HTML вместо JSON | Запрос перехватил антибот или WAF |
| Картинки не скачиваются | Нет прав на запись в `image/catalog/`, нет расширения curl, или ссылка ведёт на внутренний адрес |
